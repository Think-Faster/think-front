# Спек: несколько окон одного раздела, тёмная тема, выбор вместо ввода

Ветка `TF-Front-Workspace`. Дополняет [ARCHITECTURE.md](ARCHITECTURE.md), не заменяет его:
структура слоёв (core → entities → stores → features → widgets, `shared/ui`) не меняется.
Источник доменных правил — доменный документ (§1.1, §7.2, §11, §12.5).

## Цели

1. Разделы, которых может понадобиться несколько, открываются в нескольких окнах сразу:
   две карты разных объектов, логи двух объектов рядом, две карточки заявок.
2. Тёмная тема: переключатель в сайдбаре, выбор запоминается, без выбора — как в системе.
3. Рамки у всех полей ввода видны в обеих темах.
4. Там, где у значения есть справочник, поле даёт выбор, а не просит вписать вручную.
   Справочники не хардкодятся в формах — лежат в `*Labels.ts` своей фичи или приходят из BFF.

## 1. Экземпляры окон

Окно на холсте — экземпляр записи реестра (§7.2: `window_id` и `window_type`; §12.5 — дубли
разрешены).

| что | где |
|---|---|
| id экземпляра, номер, лимит `MAX_WINDOW_INSTANCES = 4` | `core/workspace/windowInstance.ts` |
| флаг `multiple` у записи, `findWindowDefinition`, `windowTitle` («Карта 2») | `core/registry/windowRegistry.ts` |
| контекст копии `{objectId?, entityId?}`, localStorage `kontur_instances_v1` | `stores/workspace/instanceStore.ts` |
| `useWindowObject`, `useWindowEntityId`, `openWindowWithObject`, `windowContextSnapshot` | `stores/workspace/windowScope.ts` |
| `openWindowCopy`, очистка контекста при закрытии | `stores/workspace/workspaceCommands.ts` |

Правила:

- Первый экземпляр носит id записи (`map`), копии — `map:2` … `map:4`. Сохранённые раньше
  раскладки остаются валидными.
- Первый экземпляр следует общему выбору (`selectionStore`) и адресу; копия держит свой объект
  или свою сущность и общий выбор не трогает.
- Переход в другое окно («история», «логи» из карточки) идёт через общий выбор к первому
  экземпляру целевого окна — даже если переход сделан из копии.
- «Показать на карте» исполняет только первая карта.
- Карточка (`pred`, `taskDetail`) у первого экземпляра читает `:id` своего маршрута из реестра:
  на `/tasks/:id` карточка прогноза не получает id заявки.
- Содержимое окна узнаёт свой id и маршрут через `WindowInstanceContext`, реестр не импортирует.
- Копию открывает кнопка ⧉ в шапке окна или «+» у выбранного раздела в сайдбаре — с тем, что
  окно показывает сейчас. При лимите — подсказка, окно не открывается.

`multiple: true`: `map`, `queue`, `taskQueue`, `objectHistory`, `dataLog`, `logs`, `pred`,
`taskDetail`. Остальные (настройки, люди, создание заявки) — в одном экземпляре.

## 2. Тёмная тема

- `stores/theme/themeStore.ts`: выбор `light | dark | null` (null — как в системе),
  localStorage `kontur_theme_v1`, атрибут `html[data-theme]`, слежение за
  `prefers-color-scheme`. Подключается в `index.tsx` до первого рендера.
- Переключатель — `.sidebar-theme` в верхней части сайдбара.
- CSS: все цвета — токены в `:root`; тёмные значения задаются дважды —
  `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) {…} }` и
  `:root[data-theme='dark'] {…}`. Компоненты берут цвета только из токенов; литералов цвета
  внутри тёмных блоков нет. Тени и линии — через `--shade-rgb` и `--ink-rgb`.
- Карта: свои токены `--city-*`, `--map-*` на `.map`, с тёмными значениями по той же схеме.
- Сайдбар и шапки окон на градиенте одинаковы в обеих темах.

## 3. Рамки полей

Токены `--field-bg`, `--field-border`. Базовое правило с нулевой специфичностью
(`:where(input:not([type='checkbox'], [type='radio'], [type='range'], [type='color']), textarea)`)
плюс `select`, `.form-card`, `.login-form` — на тех же токенах. Своё оформление поля в фиче
перекрывает базу без `!important`.

## 4. Выбор вместо ввода

Компоненты `shared/ui`:

- `ChoiceField` — выбор из справочника; `allowCustom` добавляет «другое…» с полем ввода для
  открытых справочников (§11: «и т.д.», «прочие»). Значение не из списка не теряется.
  `textChoiceOptions` — справочник без кодов (значение = подпись).
- `ChipMultiSelect` — несколько значений чипами.
- `ChipFilterGroup` — чипы теперь `type="button"` и не отправляют форму.

| поле | откуда варианты |
|---|---|
| заявка: вид работ, классификация неисправности | §11, `taskLabels.ts`, открытые |
| заявка: приоритет | `taskPriorityOptions` 1–5, по умолчанию `TASK_PRIORITY_DEFAULT` |
| заявка: исполнитель, кому вернуть | BFF `/tasks/assignees?role=engineers\|dispatchers` |
| датчик: подсистема, тип | BFF `GET /sensors/types` + `collector.systems`, открытые |
| датчик: пикет | BFF `/objects/{id}/pickets` по цепочке предков (`usePickets`) |
| объект: вид | виды уже заведённых объектов, открытый |
| объект: уровень | не вводится: `parent.level + 1`, у корня 1 (§1.1) |
| инженер: специализация | `engineerSpecializationLabels` (`peopleLabels.ts`) |
| график смен: источник | подписи из данных (график смен, график отпусков), открытый |
| письмо: тип | `emailKindOptions` (fact / forecast — режим рекомендации §11) |
| игнорируемый период: объект, датчик | `useObjects`; датчики выбранного объекта (`useSensors`) |

Остаются текстом: исход и номер тикета инцидента, комментарии, номера документов.

`useSensors(objectId)` грузит датчики объекта целиком (`OBJECT_SENSORS_PAGE_SIZE`): на
коллекторе их за двести, страница BFF по умолчанию — 50.

### BFF

`GET /bff/sensors/types` (`sensors:read`) — различные пары `{system, sType}` из заведённых
датчиков, по порядку. Ветка `TF-BFF-SensorOptions` в think-bff, описание — в
`FRONTEND_INTEGRATION_DOMAIN_MODELS.md`. Там же `picketId` во всех DTO — `number | null`.
При ошибке ручки фронт показывает только `collector.systems` и свободный ввод.

## Открытые вопросы

- Шкала приоритета заявки (1 — наивысший?) не утверждена.
- У вида работ и классификации неисправности нет кодов — хранится подпись; при появлении
  кодов справочник переезжает в `Record<код, подпись>`.
- Подписи видов объекта (`kind`) — сейчас сырые значения из данных.

## Проверка

- `npx tsc --noEmit -p .` и `CI=true npm run build` без ошибок и предупреждений.
- Две карты: у второй свой объект, клик по первой не меняет вторую; «показать на карте» —
  только первая.
- Логи двух объектов рядом; закрытие копии очищает её контекст; после перезагрузки копии
  открываются со своим объектом.
- Пятое окно одного раздела не открывается, видна подсказка.
- Тема: переключатель, перезагрузка, системная тема без выбора; карта и модальные окна читаемы
  в обеих темах; рамки полей видны.
- Формы из таблицы §4 предлагают выбор; неизвестное значение из старых данных не теряется.
